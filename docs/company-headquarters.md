# Company Headquarters

Super Admin navigation links to `/platform/headquarters`. Both the page and its read-only `/api/platform/workforce` endpoint use the existing `platformOwner()` check; company administrators are not granted platform access.

The read endpoint loads protected evidence from Supabase tables created by supabase/workforce-cloud.sql. Anonymous and authenticated browser roles receive no table privileges. A separately authorized cloud executor submits bounded evidence to POST /api/platform/workforce/events with a private bearer secret. The secret must contain at least 32 random characters and remain in private hosting/executor configuration. Errors fail closed.

Run records contain id, agentId, task, status, result, startedAt and finishedAt. Message records contain id, senderId, recipientId, kind, text, recordedAt and taskId. The server derives office, role and display names from registered role IDs; callers cannot impersonate arbitrary profiles. Status is Working, Completed, Blocked or Failed. Keep secrets and raw client records out. Batches are limited to 50 runs and 50 messages, input is limited to 300 KB, upserts are idempotent by external ID, and only the latest 300 records are shown.

Polling occurs every ten seconds. Movement is decorative and enabled only while recent data records a Working task. Updates older than ten minutes suppress movement and show stale history; this threshold is a display safeguard, not proof a task has stopped. Pausing movement and system reduced-motion preferences are supported. Task history is not a financial progress metric. Live progress, CEO approvals, client provisioning and continuous execution require separate verified integrations; this view does not perform those actions.

Deployment acceptance: apply the SQL migration, set a unique ingestion secret in both hosting and the approved executor, verify anonymous and company-admin denial, reject invalid role IDs and invalid secrets, confirm authorized platform-owner rendering, stale-feed behavior, reduced motion, and an actual worker run independent of a user's computer before calling this a cloud workforce. Review and approve the release before production deployment.
