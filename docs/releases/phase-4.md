# Phase 4 — maintenance, inventory and Calendar

Work orders retain the existing operational status queue, tenant entry/pet information, scheduling and attachments. Saved orders have a protected Letter PDF job sheet, inventory shortcut and correct-unit owner-charge shortcut. Operational job sheets exclude owner balances, DLA income and bulk supplier costs. Print access uses current authenticated roles and assigned-property scope; PDFs are private, uncached and 612 × 792 points. The filtered work register and Calendar agenda print all matching records, independently of pagination.

Calendar includes Administrative, Announcements and Maintenance events plus scheduled work. Leasing tours/expiry reminders are removed from this client calendar. Legacy unsupported event records remain preserved; new unsupported categories reject. Existing events have inline cancel/delete-to-trash confirmation with approval requests for non-manager staff. Management can restore records in the existing Approval center. Financially linked work orders cannot be deleted. Typed ISO dates and a native calendar picker are available in manager operational/procurement forms.

Accounting contains Procurement & inventory, using the same shared component and records as the Maintenance shortcut. Bulk purchase costs, stock FIFO cents and owner list-price charges remain separate. Materials usage links a same-unit active work order and an editable owner statement; returns create recoverable stock and owner credits. Immutable source histories tolerate database object-key ordering. Invalid decimal input blocks saving. Approved, completed labor posts once to the latest draft owner statement, with exact half-up cents, locked posted inputs and preserved source evidence. New charges remain provisional until the Phase 3 verified GL classification workflow is completed.

Validation: 79 core checks, 34 access assertions, 20 foundation scenarios, 26 tenancy scenarios, 31 finance/GL scenarios and 17 maintenance/print scenarios. Production build, actual HTTP role/print/approval tests with a disposable provider, and browser work/labor/inventory/event checks are required before release.

No new database migration, dependency or hosting environment variable. No live financial entries, QBO postings or email sends. Microsoft 365 notification/reply handling and native QBO exchange are Phase 6; owner distribution/close packages are Phase 5. Existing records and unit 106's confirmed occupied status must not be replaced with test data or a historical backup.
