# QBO connection setup and acceptance

This optional integration downloads records for review in Accounting > QBO exports. It sends no accounting writes. Intuit's accounting OAuth scope allows wider operations than OG uses; the OG routes restrict their operations to reads. Existing CSV import/export review controls stay available.

1. Register an Intuit developer app for QuickBooks Online. Use a sandbox company first. Configure the exact HTTPS redirect URI `<published OG origin>/api/qbo/callback`. Use credentials for the selected environment only. Do not use the GoDaddy management dashboard URL as OG_APP_URL.
2. Devonshire Supabase was prepared on October 5, 2026 and verified empty, with no browser grants. For a new installation, prepare Supabase using `supabase/qbo-connection-setup.sql`. This creates a separate private credential table and atomic lease function. Browser roles get no access. It changes no financial record or staff membership. Never include credentials in OG financial backups.
3. Enter private hosting settings: OG_QBO_CLIENT_ID, OG_QBO_CLIENT_SECRET, OG_QBO_ENVIRONMENT (`sandbox` or `production`), OG_QBO_EXPECTED_REALM_ID (exact company ID), OG_QBO_EXPECTED_COMPANY_NAME (QBO CompanyInfo CompanyName), and OG_QBO_ENCRYPTION_KEY (base64 encoding of 32 securely random bytes). Keep the key in secure hosting configuration, never chat or source control. OG_APP_URL must be the exact HTTPS app origin. Key/client/environment/company changes require reconnection. Keep OG_QBO_ENABLED=false until setup is ready.
4. Enable OG_QBO_ENABLED=true after staging setup. Sign in as Global Admin and use Connect QuickBooks in Accounting. Intuit consent must select the approved company. The callback binds the initiating actor/workspace and request state; wrong companies and stale callbacks fail. If wrong-company consent was granted, revoke that grant in Intuit Connected Apps.
5. Test all five download buttons in sandbox, including Cash and Accrual P&L by Class. Compare IDs, dates, names, totals, class columns, and full page coverage with QBO. Verify another Global Admin sees the same server-managed connection; Management/Accountant/External CPA can download but cannot connect/disconnect; scoped staff cannot use the service. Confirm no QBO transactions or OG balances changed.
6. Register production credentials and exact production realm/name; repeat consent and acceptance for Devonshire. Capture a source ZIP and compare the October payment total, chart and class report to QBO. Live provider acceptance is required before calling Phase 6 complete. Production activation is not implied by publishing this source.

Downloads contain review.csv, qbo-source.json, SHA-256 of original source JSON and review instructions. Contacts retain QBO IDs and exact display names; they do not create tenants, owners, or vendors automatically. Payment CSV uses API IDs as stable transaction references; review effective tenant and unit, payment method and rent-charge match in Tenant rent > QBO payment import. Unapplied customer payments are not automatically treated as earned rent or pool contributions. Deposit bank account / linked invoices / original payment metadata remain in the source JSON for review. Zero void payments are excluded from the review CSV but retained in source. Negative payments, fractional cents, non-USD payments and incomplete customer references are blocked for separate review.

The chart adapter preserves QBO account IDs and full qualified account names. Confirm all three separate bank mappings and DLA income mappings in the existing GL workflow. Profit and Loss by Class is a comparison report, not evidence of collected rent or owner cash entitlement. Customer and vendor downloads include inactive records when QBO query support allows them. Entity downloads cap at four pages of 1,000 and discard the whole partial result at that limit; use a filtered QBO export for larger lists.

Concurrent requests use an atomic database lease. Token rotation is saved before another provider read; failed or uncertain refresh requires reconnection instead of retrying a potentially invalid token. Removing OG access clears stored credentials; also revoke the Intuit grant in Connected Apps if you want provider-side revocation. No email is sent. Mail/Microsoft activation continues under the separate Phase 6 setup guide.

Reference: [Intuit OAuth client](https://github.com/intuit/oauth-jsclient), [OAuth documentation](https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0), [modern reports migration](https://medium.com/intuitdev/upcoming-changes-to-reports-apis-5083ec9aadce), [class report support](https://quickbooks.intuit.com/learn-support/en-global/help-article/class-list/run-reports-class/L73XjI7rG_ROW_en), [report column enum](https://static.developer.intuit.com/sdkdocs/qbv3doc/ipp-v3-java-devkit-javadoc/com/intuit/ipp/data/SummarizeColumnsByEnum.html).

CSV prefixes formula-like text with an apostrophe for spreadsheet safety. Original exact values remain in qbo-source.json. Review that source before importing unusually named accounts/contacts. Admin logs record connection requests, verified callbacks, requested downloads and prepared downloads without tokens. No provider-side grant revocation is implied by local disconnect.
